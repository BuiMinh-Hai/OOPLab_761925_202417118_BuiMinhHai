1. The main responsibilities in my program are handling command-line input, tokenizing and normalizing the text, counting the frequency of each token, sorting the tokens alphabetically, and formatting the output string.
2. I implemented the solution using multiple classes . This decision was made to adhere to Object-Oriented Programming (OOP) principles, specifically the Single Responsibility Principle, which ensures that the code is modular, readable, and highly maintainable.
3. The program utilizes three classes. The "TokenAnalyzer" class contains the main method and is strictly responsible for program startup, receiving arguments, and managing the high-level workflow. The "TokenCounter" class handles the core business logic, including text normalization (lowercasing), token splitting, and frequency counting using a sorted TreeMap. The "ResultFormatter" class is solely responsible for taking the processed data map and transforming it into the exact string format required for output.
4. This design makes the program extremely easy to modify in the future. If the normalization rules or sorting criteria change, I only need to update the logic inside the "TokenCounter" class without touching the rest of the application. Similarly, if a new output format is required later, I can safely modify just the "ResultFormatter" class.
